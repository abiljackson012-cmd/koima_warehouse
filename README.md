# Қойма — тауар дүкені және қойма басқару жүйесі

Курстық жұмыс. Тауарларды фотосымен көрсетеді, сатып алушыларға себет пен тапсырыс береді, ал қойма қызметкерлеріне кіріс-шығысты басқаруға мүмкіндік береді.

## Мүмкіндіктер

- **Авторизация:** тіркелу, кіру, шығу. Токен HttpOnly cookie-де сақталады, шыққанда токен жарамсыз етіледі.
- **Рөлдер:**

| Рөл | Не істей алады |
|---|---|
| `buyer` (Сатып алушы) | Тауарларды көру, себетке қосу, тапсырыс беру, өз тапсырыстарын көру. Тіркелген кез келген адамға автоматты беріледі |
| `manager` (Меңгеруші) | Тауар қосу және өзгерту, фото жүктеу, кіріс және шығыс, барлық тапсырыстарды көру, тапсырысты орындалды деп белгілеу |
| `admin` (Әкімші) | Бәрі, сонымен қатар тауарды жою және қолданушыларды басқару |

- **Себет және тапсырыс:** себеттегі тауар қалдықпен тексеріледі. Тапсырыс берілгенде қалдық автоматты азаяды және қозғалыс тарихына тіркеледі. Қалдық жетпесе, бүкіл тапсырыс қабылданбайды, ешбір тауар азаймайды.
- **Тауар суреттері:** әр тауарға фото жүктеледі (JPG, PNG, WEBP, 3 МБ-қа дейін). Файлдың шын түрі мазмұны бойынша тексеріледі, тек кеңейтімі бойынша емес. Фотосыз тауарға атауының бас әрпі көрсетіледі.
- **Негізгі бизнес-логика:** тауар CRUD, кіріс/шығыс, қалдығы аз тауарларды белгілеу, қойма құнын есептеу, қозғалыс тарихы.
- **Валидация:** барлық кіріс деректері `pydantic` арқылы тексеріледі (түрі, ұзындығы, формат, белгісіз өрістерге тыйым).
- **Error handling:** барлық қате бірыңғай JSON форматымен қайтады, дұрыс HTTP кодтарымен.
- **Testing:** 57 автоматты тест (`pytest`).

## Технологиялар

| Қабат | Технология |
|---|---|
| Frontend | HTML, CSS, JavaScript (`app/static/`) |
| Backend | Python 3, Flask, REST API (JSON) |
| Database | SQLite (әдепкі) немесе PostgreSQL (Neon, Supabase, Railway) |
| Авторизация | JWT (PyJWT), құпиясөз хэші `scrypt` (Werkzeug) |
| Валидация | pydantic |
| Тест | pytest |

## Жоба құрылымы

```
app/
  __init__.py      Flask қолданбасын құру, логтау, бастапқы деректер
  config.py        .env оқу
  db.py            SQLite / PostgreSQL қабаты, кестелер схемасы
  auth.py          JWT, рөлдерді қорғау (@require)
  validation.py    pydantic модельдері, қазақша қате хабарлары
  errors.py        қателерді өңдеу
  seed.py          admin/manager аккаунттары және 20 демо-тауар
  routes/          auth.py, products.py, users.py, cart.py, orders.py
  static/          index.html, style.css, app.js (интерфейс)
  static/uploads/  жүктелген тауар суреттері (Git-ке кірмейді)
tests/             57 тест
run.py             жергілікті іске қосу
Procfile           хостингте іске қосу (gunicorn)
.env.example       баптаулар үлгісі
```

## Жергілікті іске қосу

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt

copy .env.example .env            # Windows (macOS/Linux: cp .env.example .env)
# .env ашып, SECRET_KEY және аккаунт құпиясөздерін өзгертіңіз

python run.py
```

Сайт: http://127.0.0.1:5000

Бірінші іске қосуда база мен кестелер өздігінен жасалады. `.env`-тегі `ADMIN_*` және `MANAGER_*` аккаунттары қосылады. `SEED_DEMO_DATA=1` болса, 20 демо-тауар да қосылады.

Ескерту: егер бұрын `warehouse.db` файлы жасалған болса, оны жойып, қайта іске қосыңыз, себебі жаңа нұсқа кестелерді өзгертеді.

## Тауарға фото қосу

1. Меңгеруші немесе әкімші ретінде кіріңіз.
2. Тауар карточкасындағы **«Өңдеу»** батырмасын басыңыз.
3. **«Сурет»** бөлімінде файлды таңдаңыз (JPG, PNG немесе WEBP, 3 МБ-қа дейін).
4. **«Сақтау»** батырмасын басыңыз. Фото бірден карточкада көрінеді.

## .env айнымалылары

| Айнымалы | Мағынасы |
|---|---|
| `SECRET_KEY` | JWT қол қою кілті, кемінде 32 таңба. Жасырын сақталады |
| `DATABASE_URL` | Бос қалдырса, SQLite (`warehouse.db`). PostgreSQL үшін `postgresql://user:pass@host/db` |
| `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Бастапқы әкімші |
| `MANAGER_USERNAME`, `MANAGER_EMAIL`, `MANAGER_PASSWORD` | Бастапқы меңгеруші |
| `SEED_DEMO_DATA` | `1` болса, бос базаға демо-тауарлар қосылады |
| `TOKEN_HOURS` | Токеннің жарамдылық мерзімі, сағатпен (әдепкі 8) |
| `COOKIE_SECURE` | HTTPS хостингте `1` қойыңыз |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING` |

`.env` файлы `.gitignore`-да тұр, GitHub-қа жүктелмейді.

## REST API

Жауаптар JSON форматында. Жүйеге кіргеннен кейін токен cookie-де автоматты жіберіледі (не `Authorization: Bearer <token>` тақырыбымен).

| Method | URL | Рөл | Сипаттамасы |
|---|---|---|---|
| POST | `/api/auth/register` | — | Тіркелу (рөлі `buyer`) |
| POST | `/api/auth/login` | — | Кіру |
| POST | `/api/auth/logout` | кез келген | Шығу, токен жарамсыз болады |
| GET | `/api/auth/me` | кез келген | Ағымдағы қолданушы |
| GET | `/api/products` | кез келген | Тізім. `search`, `low=1`, `limit`, `offset` |
| GET | `/api/products/<id>` | кез келген | Бір тауар |
| POST | `/api/products` | manager, admin | Тауар қосу |
| PUT | `/api/products/<id>` | manager, admin | Толық өзгерту |
| PATCH | `/api/products/<id>` | manager, admin | Жартылай өзгерту |
| POST | `/api/products/<id>/image` | manager, admin | Фото жүктеу (`multipart/form-data`, өрісі `image`) |
| DELETE | `/api/products/<id>` | admin | Жою (фотосы да жойылады) |
| POST | `/api/products/<id>/movements` | manager, admin | Кіріс/шығыс: `{"type":"in\|out","quantity":5}` |
| GET | `/api/movements` | кез келген | Қозғалыс тарихы |
| GET | `/api/stats` | кез келген | Қойма статистикасы |
| GET | `/api/cart` | кез келген | Өз себеті |
| POST | `/api/cart` | кез келген | Себетке қосу: `{"product_id":1,"quantity":2}` |
| PATCH | `/api/cart/<product_id>` | кез келген | Санын өзгерту, 0 болса алып тастайды |
| DELETE | `/api/cart/<product_id>` | кез келген | Себеттен алып тастау |
| POST | `/api/orders` | кез келген | Себеттен тапсырыс беру (қалдық автоматты азаяды) |
| GET | `/api/orders` | кез келген | Өз тапсырыстары (меңгеруші мен әкімші үшін бәрі) |
| PATCH | `/api/orders/<id>` | manager, admin | Күйі: `{"status":"done"}` |
| GET | `/api/users` | admin | Қолданушылар тізімі |
| PATCH | `/api/users/<id>` | admin | Рөлді өзгерту: `{"role":"manager"}` |
| DELETE | `/api/users/<id>` | admin | Аккаунтты жою |
| GET | `/api/health` | — | Сервер жұмысын тексеру |

**HTTP кодтары:** `200` сәтті, `201` жасалды, `204` жойылды, `400` JSON қате, `401` кірмеген немесе токен жарамсыз, `403` рұқсат жоқ, `404` табылмады, `409` қайшылық (логин/артикул бос емес, қалдық жеткіліксіз), `413` файл тым үлкен, `422` валидация қатесі, `429` тым көп сәтсіз кіру әрекеті, `500` сервер қатесі.

**Қате форматы:**

```json
{"error": {"code": "validation_error", "message": "Енгізілген деректерде қате бар.",
           "details": [{"field": "price", "message": "Мәні 0-ден кем болмауы керек."}]}}
```

## Қауіпсіздік

- Құпиясөздер ашық күйінде сақталмайды, `scrypt` хэші ғана сақталады.
- Токен `HttpOnly` + `SameSite=Lax` cookie-де. JavaScript оны оқи алмайды.
- Логинді таңдап бұзудан қорғау: 5 минутта 5 сәтсіз әрекеттен кейін 429.
- Қате логин мен қате құпиясөзге бірдей жауап беріледі (аккаунттың бар-жоғы білінбейді).
- Тіркелу арқылы тек `buyer` рөлін алуға болады, рөлді өзгертуге тек `admin` құқылы.
- Рөл әр сұраныста базадан тексеріледі, сондықтан рөл өзгергенде бірден күшіне енеді.
- Сурет жүктеуде файлдың шын түрі мазмұны бойынша тексеріледі, өлшем шегі бар.
- Қалдық тек шартты `UPDATE ... WHERE quantity >= ?` арқылы азаяды, сондықтан минусқа кетпейді. Тапсырыс бір бөлігі сәтсіз болса, толық қайтарылады.
- SQL сұраныстары параметрлермен жазылған (SQL injection-нан қорғау), интерфейсте мәтін экрандалады (XSS-тен қорғау).

## Тестілеу

```bash
python -m pytest -v
```

57 тест тексереді: тіркелу және кіру валидациясы, токеннің жарамсыздығы, рөлдер бойынша рұқсат, тауар CRUD, кіріс/шығыс, себет (қалдықтан асыру, жеке себет), тапсырыс (атомарлық азайту және толық қайтару), тапсырыстардың көрінуі, фото жүктеу (түрі, өлшемі, рұқсат, файлды жою), қолданушыларды басқару.

## Debugging

- Маңызды оқиғалар (кіру, сәтсіз кіру, тауар және тапсырыс операциялары, рөл ауысуы) консольге және `logs/app.log` файлына жазылады.
- Күтпеген қате болса, қолданушыға жалпы хабар көрсетіледі, толық себебі `logs/app.log` ішінде қалады.
- Браузерде: F12 → Network қойындысында әр API сұранысының коды мен JSON жауабы көрінеді.

## PostgreSQL-ға (Neon / Supabase / Railway) өту

1. Жаңа база жасап, байланыс жолын (connection string) көшіріңіз.
2. `.env` ішінде жазыңыз: `DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require`
3. `pip install -r requirements.txt`, `python run.py`. Кестелер өздігінен жасалады.

Ескерту: PostgreSQL жолы тек кодта жазылған, бірақ бұл жобада нақты іске қосылып тексерілмеген.

## Хостингке шығару (Render мысалы)

1. Кодты GitHub-қа жүктеңіз.
2. Render.com → New → Web Service → GitHub репозиторийін таңдаңыз.
3. Build command: `pip install -r requirements.txt`. Start command: `gunicorn "app:create_app()"`.
4. Environment бөліміне `.env` мәндерін қосыңыз (`SECRET_KEY`, `DATABASE_URL`, `ADMIN_*`, `MANAGER_*`, `COOKIE_SECURE=1`).
5. Хостингте SQLite және жүктелген фотолар қайта іске қосылғанда жоғалуы мүмкін. Сондықтан PostgreSQL және тұрақты диск немесе сурет сақтау қызметін (мысалы, Cloudinary) қолданыңыз.

## Git жұмыс процесі

- `main` — тұрақты нұсқа.
- Әр бөлім бөлек branch-та жасалып, Merge арқылы `main`-ге қосылған: `feature/backend`, `feature/frontend`, `feature/tests`, `docs/readme`, `feature/cart-photos`.
- Тарихты қарау: `git log --oneline --graph --all`.

## Белгілі шектеулер

- Төлем жүйесі жоқ. Тапсырыс тек қойма қызметкеріне жіберіледі, оны ол орындалды деп белгілейді.
- Тапсырыс күйі тек `new` және `done`.
- Email растау және құпиясөзді қалпына келтіру жоқ.
- Логинді бұғаттау есебі сервердің жадында сақталады. Сервер қайта қосылса, нөлге түседі.
